# Quantization, Difficulty, and Item Response Theory

**A Proposed Framework and Pre-specified Protocol for Testing When Psychometric Difficulty Signals Survive Compression**

This repository accompanies a **proposal / methods paper**. It contributes a framework,
a falsifiable pre-specified protocol, and a runnable reference implementation for testing
whether Item Response Theory (IRT) item difficulty survives model quantization.

> **This is not an empirical findings paper.** No experimental results are claimed. The
> figures in the paper are illustrative schematics. `example_findings.json` documents the
> output *format* only and contains placeholder values, not measurements.

## What this is

A method for treating each `(model, quantization-level)` pair as an IRT "subject," plus
five pre-specified probes — each with a stated positive/negative decision rule. The numeric
margins that the rules for Probes 1–4 require are to be pre-specified before data collection
and are not yet fixed:

1. **Probe 1** — does IRT recover item difficulty from quantization subjects?
2. **Probe 2** — does accuracy mask difficulty-dependent degradation (vs. KL)?
3. **Probe 3** — does any within-family effect replicate cross-family?
4. **Probe 4** — does IRT beat simple averaging (dense vs. sparse)?
5. **Probe 5** — is there a difficulty-dependent DIF shift between precision groups?

## Reference implementation

```
code/run_eval.py        # prompt-only next-token option scoring (llama.cpp)
code/analyze_all.py     # 2PL IRT (+masked likelihood), KL, DIF, bootstrap, sparse sim
code/make_figs.py       # plots real data if results/*.jsonl present, else labeled schematics
scripts/check_manifest.py  # verifies inputs present before analysis
```

## How to run it (with your own data)

The protocol is designed to be executed by supplying your own scored response matrices:

```bash
pip install -r requirements-analysis.txt   # add -r requirements-scoring.txt to score models

# 1. Score models on a benchmark -> results/*.jsonl  (needs GGUF weights + llama.cpp)
FAMILY=qwen python code/run_eval.py f16 /path/to/qwen2.5-0.5b-f16.gguf 100

# 2. Verify inputs
python scripts/check_manifest.py     # prints READY when data/items.json + results/*.jsonl exist

# 3. Run all five probes -> findings.json (real, measured output)
python code/analyze_all.py

# 4. Generate figures from real data (replaces the illustrative schematics)
python code/make_figs.py
```

When real `results/*.jsonl` are present, `make_figs.py` plots measured per-item data and the
"ILLUSTRATIVE SCHEMATIC" banner disappears. Without them, it renders clearly-labeled schematics.
